# DECISIONS

One line per decision: what was decided, and what was rejected. Newest last within a
section. A decision that turns out wrong gets a new entry, not an edit.

## Locked

| Date | Decision | Alternative rejected |
|---|---|---|
| 2026-08-15 | **Trace format** — an event log mapped to the OTel GenAI semconv: an `invoke_agent` → `chat` → `execute_tool` span tree, `gen_ai.*` attributes, content in span events. Agents already emitting OTel need no adapter. Semconv is Development status, so its version is pinned in the lockfile. | A bespoke trace schema — it would need an adapter per framework and would not accept production traces. |
| 2026-08-15 | **Agent interface** — one `AgentAdapter` protocol: `async run(messages, tools, config) -> events`, plus an optional `describe() -> {tools, edges, cycles, hitl_points}`. Raw OTLP traces are also accepted as input. | Per-framework integrations; a required `describe()` that would exclude raw-SDK agents. |
| 2026-08-15 | **Lockfile** — `spec.lock.toml` pins judge model, rubric hash per card, simulator model and prompt hash, and semconv version. The runner refuses a stale lock without `--relock`. | Trusting the judge model string alone: rubric text drifts silently, which is the failure the lockfile exists to catch. |
| 2026-08-15 | **Statistics** — a cell passes when ≥k of N runs pass (default N=5, k=4). Reports pass rate, variance, latency p50/p95, and a dollar estimate. | Single-run pass/fail — it reads nondeterminism as a regression. |
| 2026-08-15 | **Cost** — a per-provider rate table in TOML; every figure labeled an estimate. | Live pricing APIs, and unlabeled figures that read as billing. |
| 2026-08-15 | **Waste classifiers** — port cctx's retry-loop and stale-context classifiers to the trace and attribute per cell. | Writing new classifiers; the cctx ones are already validated against real sessions. |
| 2026-08-15 | **Simulator** — pinned like the judge, with its version printed in every report. | Leaving it unpinned: simulator benevolence bias shifts pass rates with no card change. |
| 2026-08-15 | **Wire palette** — Dwyer patterns (`never`, `at_most`, `eventually`, after-K-then-Y, precedence) × scopes (globally, between events, after K occurrences) × event selectors from OTel GenAI vocabulary. | A general temporal logic — unbounded surface, unteachable to an SME, and unnecessary for the patterns real cards need. |
| 2026-08-15 | **One property, three deployment modes** — eval assertion, CI gate, and later an AgentSpec-style runtime monitor. Ship the first two; design the IR so the third needs no format change. | Separate formats per mode, which would fork the spec. |
| 2026-08-15 | **License and language** — MIT. Python 3.11+, `uv`. Dependencies beyond `httpx`, `pydantic`, `typer`, and `rich` require an explicit ask. | A heavier default dependency set; a copyleft license, which would block adoption inside companies. |
| 2026-08-15 | **Parser scope** — a ~50-line parser over the card's four blocks. | Gherkin and step definitions: a second language to learn, and step definitions land the SME back in code. |
| 2026-08-15 | **Coverage never gates CI**, with one exception: per-feature definition obligations, which are binary and non-gameable. | Coverage percentage thresholds — gameable, and they punish honest denominators. |
| 2026-08-15 | **Governance** — the card format and property IR spec live in a separate repo under a permissive license, from day one. | Keeping the format inside the runner repo, which couples format stability to runner churn. |
| 2026-08-15 | **Progress tracking lives in GitHub milestones and issues**, one milestone per phase. PRODUCT.md holds personas, principles, non-goals, and kill criteria only. | A roadmap section in PRODUCT.md — it drifts from the real issue state, and nothing makes anyone notice. |
| 2026-08-15 | **Each gated phase ends in a kill-gate decision issue** (#31, #35) that closes with a recorded outcome, either way. | Letting a milestone close when its last feature issue closes — that records that work finished, not that the gate was evaluated. |
| 2026-08-16 | **Execution backend** — our own loop. The IR, judge, and trace schema are backend-independent and stay that way; Inspect logs are an accepted trace source, not the runner. One τ-bench card ran both ways over four agent scripts with zero verdict disagreement. The deciding fact: the trace comes from the adapter or from raw OTLP, so a harness transcript is never the agent's trace source — and Inspect emits no `ToolEvent` at all for a bridged agent, which is what a user-owned agent is. [Report](docs/spikes/execution-backend.md). | Compiling cards to Inspect `Task`s: it buys sandboxing for code specdeck never executes, provider portability needed at two call sites, and an audit log of a run whose trace already arrives by another route, while coupling the card format to Inspect's `Task` surface. |
| 2026-08-16 | **Domain events in the event-selector vocabulary** — a reserved `specdeck.*` attribute namespace, stamped on the span it describes, with the legal marker names declared alongside the tool vocabulary so lint rejects an unknown one. In an eval the simulator stamps them; in production the agent's own instrumentation does, which is what lets the same property serve the runtime monitor. | Domain events as first-class spans, which would put non-semconv spans in a log whose value is that it *is* the semconv; and dropping the concept, which would cost the format its escalation wire and rewrite its own example card. |
| 2026-08-16 | **Wire palette, superseding the 2026-08-15 entry** — the Dwyer patterns **plus bounds** over a fixed, introspectable measure vocabulary. `latency: under 120s` and `response_tokens under 400` are bounds, and no Dwyer pattern expresses them: `response_tokens` is a sum across `chat` spans, so no event selector reaches it. Lint rejects an unknown measure the way it rejects an unknown tool. | Dropping bounds from the card format, which would make a latency budget report-only and remove two wires from the format's own example card. |
| 2026-08-24 | **The simulator reports its own marker** — each simulated turn returns `{reply, marker, done}`, and an undeclared marker is refused rather than stamped. It is the party that knows whether it accepted the answer. | A second classifier call per turn to infer the marker: it doubles simulator calls and adds a second pinned prompt to grade a reaction it did not have. The cost accepted is that the simulator scores its own state, which is why the marker vocabulary is declared and enforced. |
| 2026-08-24 | **The provider seam is one function, `complete()`, and a bare model string means Anthropic** — a prefix (`openai/gpt-5`) names a departure from the default. | Requiring a prefix everywhere: `spec.lock.toml` pins `claude-sonnet-5` and every cassette keys on the model string, so it would re-key every recording on disk and cost a live call each to record what is already there. A plugin registry was also rejected — two call sites do not need one. |
| 2026-08-24 | **A conversation ends when the simulator says `done`**, with `--max-turns` as a backstop. | Ending only on a turn cap: every run would then finish mid-argument, and the cap would silently become the scenario's length rather than its limit. |
| 2026-08-24 | **Card-mechanics language in prose is a lint warning**, carved out of "never style-police the SME zone". Prose describing the card's own pass/fail machinery — "do not fail this card", "fails only if", ALL-CAPS emphasis — reproducibly makes the judge return commentary instead of verdicts, and an ungraded criterion fails closed. Warning, never error: the SME's words stay theirs. | A suggestion, which the severity rule as written implies and which never blocks — it would have hinted at two wasted live judge calls rather than prevented them. And an error, which would put lint in a position to reject the SME's own prose. |
| 2026-08-24 | **The lockfile pins the wire block too**, in its own `wires_hash` per card, computed from the compiled property IR rather than the wire text. | Folding wires into `rubric_hash`: a stale-lock error could then no longer say whether the prose or the wires moved, and those are owned by different people. And leaving wires unpinned, which let `modify_reservation: never` be deleted while the lock verified clean and the cell ran green. |
| 2026-08-24 | **The cost rate table is a data file, not a lock pin** — a built-in `src/specdeck/rates.toml` of per-provider, per-model USD-per-million-token input and output rates, optionally merged under a `rates.toml` beside the card, carrying a `verified` date that every rendered figure prints. A model with no entry yields no number at all — `n/a` naming the model, never a substituted rate and never $0.00. | A `[rates]` section of `spec.lock.toml`: `--relock` rewrites that file from a fixed template and would drop it, and an ordinary vendor price refresh would then read as card drift on every card. And cctx's mid-range default for an unrecognised model — it prices sessions that already happened, where a plausible figure beats nothing; specdeck reports a live run, where a fabricated rate would put an invented number in front of a user as if it had been measured. |
| 2026-08-24 | **A rate key prices its own family and that family's dated ids, nothing else** — a match is accepted only where the rest of the model id is empty or a `-YYYYMMDD` release date. | Bare longest-prefix matching: `claude-opus-4-9` would inherit the retired `claude-opus-4` price at three times the Opus tier, which is the substituted rate #16(b) exists to forbid, printed as a confident estimate. |
| 2026-08-24 | **A merged rate table carries the older of the two `verified` dates.** | Taking the override's date wholesale: an override that only adds a model restates nothing about the built-in rows, so its date would stamp figures nobody rechecked with a freshness claim nobody made. |
| 2026-08-24 | **Variance is the spread of per-run credit over the passing runs** — the min-max range and the population standard deviation, taken over exactly the set `credit_mean` is taken over, plus a "gate mixed, 4 pass / 1 fail" clause only when the gate itself went both ways. The 2026-08-15 entry said the cell reports "variance" and left the term undefined; this defines it. No UNSTABLE verdict and no quarantine lane — those stay with variance attribution, a later phase, because they would change the exit-code contract. | The binomial standard deviation of the gate pass rate: it mostly restates the "4/5 runs" the headline already prints, while the credit headline is the number that actually hides something — "credit 3/3 over 4 passing runs" reads identically whether the runs scored 3, 3, 3, 3 or 1, 3, 3, 5. |
| 2026-08-24 | **The dollar estimate prices the agent's traced tokens only**, and the report line says "agent tokens only" rather than leaving the scope to be assumed. specdeck's own judge and simulator spend is not in the figure ([#80](https://github.com/jacquardlabs/specdeck/issues/80)). | Pricing specdeck's own spend now: `provider.complete` returns a bare string and a cassette stores only the reply text, so it would mean widening the provider seam and re-recording every cassette — and cassettes are Phase 3 mutation-runner fixtures, not throwaway recordings. Inventing the counts instead was never on the table. |
| 2026-08-24 | **Per-model usage read off a trace carries the provider in the model id** — `Trace.usage_by_model` keys on `gen_ai.response.model` prefixed with `gen_ai.provider.name` when it names a real one, so `openai/gpt-4o` prices against a `[rates.openai]` section the user added. A bare id stays bare, the way `provider.split_model` already reads one. | Keying on the bare id and passing a `provider=` override at each pricing call site: nothing did, so a model the default provider never serves read as unpriced even when the resolved table priced it — and #17's baseline and #15's cap would have inherited the same blindness from the same shared surface. A `(provider, model)` tuple key was also rejected: it widens the surface two later waves read, for information the id already carries. |
| 2026-08-24 | **A `rates.toml` merely found beside the card cannot abort a run** — a broken one prints a note naming the file and the run continues on the built-in table; a table named on `--rates` still exits 2, because the user asked for that table. | Exit 2 on both paths: an unrequested optional file pricing a dim secondary figure would stop a card that had nothing wrong with it, and README documents exit 2 as "the run could not start". Reporting `n/a` instead of the built-in figure was also rejected — the cost line would then read "no rate table" when there is one, and threading the reason into the report is scope this wave does not have. |
