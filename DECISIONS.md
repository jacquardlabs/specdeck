# DECISIONS

One line per decision: what was decided, and what was rejected. Newest last within a
section. A decision that turns out wrong gets a new entry, not an edit.

## Locked

| Date | Decision | Alternative rejected |
|---|---|---|
| 2026-08-15 | **Trace format** — an event log mapped to the OTel GenAI semconv: an `invoke_agent` → `chat` → `execute_tool` span tree, `gen_ai.*` attributes, content in span events. Agents already emitting OTel need no adapter. Semconv is Development status, so its version is pinned in the lockfile. | A bespoke trace schema — it would need an adapter per framework and would not accept production traces. |
| 2026-08-15 | **Agent interface** — one `AgentAdapter` protocol: `async run(messages, tools, config) -> events`, plus an optional `describe() -> {tools, edges, cycles, hitl_points}`. Raw OTLP traces are also accepted as input. | Per-framework integrations; a required `describe()` that would exclude raw-SDK agents. |
| 2026-08-15 | **Lockfile** — `spec.lock.toml` pins judge model, rubric hash per card, simulator model and prompt hash, and semconv version. The runner refuses a stale lock without `--relock`. | Trusting the judge model string alone: rubric text drifts silently, which is the failure the lockfile exists to catch. |
| 2026-08-15 | **Statistics** — a cell passes when ≥k of N runs pass (default N=5, k=4). Reports pass rate, variance, latency p50/p95, and a dollar estimate. | Single-run pass/fail — it reads nondeterminism as a regression. |
| 2026-08-15 | **Cost** — a per-provider rate table in TOML; every figure labeled an estimate. | Live pricing APIs, and unlabeled figures that read as billing. |
| 2026-08-15 | **Waste classifiers** — port cctx's retry-loop and stale-context classifiers to the trace and attribute per cell. | Writing new classifiers; the cctx ones are already validated against real sessions. |
| 2026-08-15 | **Simulator** — pinned like the judge, with its version printed in every report. | Leaving it unpinned: simulator benevolence bias shifts pass rates with no card change. |
| 2026-08-15 | **Wire palette** — Dwyer patterns (`never`, `at_most`, `eventually`, after-K-then-Y, precedence) × scopes (globally, between events, after K occurrences) × event selectors from OTel GenAI vocabulary. | A general temporal logic — unbounded surface, unteachable to an SME, and unnecessary for the patterns real cards need. |
| 2026-08-15 | **One property, three deployment modes** — eval assertion, CI gate, and later an AgentSpec-style runtime monitor. Ship the first two; design the IR so the third needs no format change. | Separate formats per mode, which would fork the spec. |
| 2026-08-15 | **License and language** — MIT. Python 3.11+, `uv`. Dependencies beyond `httpx`, `pydantic`, `typer`, and `rich` require an explicit ask. | A heavier default dependency set; a copyleft license, which would block adoption inside companies. |
| 2026-08-15 | **Parser scope** — a ~50-line parser over the card's four blocks. | Gherkin and step definitions: a second language to learn, and step definitions land the SME back in code. |
| 2026-08-15 | **Coverage never gates CI**, with one exception: per-feature definition obligations, which are binary and non-gameable. | Coverage percentage thresholds — gameable, and they punish honest denominators. |
| 2026-08-15 | **Governance** — the card format and property IR spec live in a separate repo under a permissive license, from day one. | Keeping the format inside the runner repo, which couples format stability to runner churn. |
| 2026-08-15 | **Progress tracking lives in GitHub milestones and issues**, one milestone per phase. PRODUCT.md holds personas, principles, non-goals, and kill criteria only. | A roadmap section in PRODUCT.md — it drifts from the real issue state, and nothing makes anyone notice. |
| 2026-08-15 | **Each gated phase ends in a kill-gate decision issue** (#31, #35) that closes with a recorded outcome, either way. | Letting a milestone close when its last feature issue closes — that records that work finished, not that the gate was evaluated. |
| 2026-08-16 | **Execution backend** — our own loop. The IR, judge, and trace schema are backend-independent and stay that way; Inspect logs are an accepted trace source, not the runner. One τ-bench card ran both ways over four agent scripts with zero verdict disagreement. The deciding fact: the trace comes from the adapter or from raw OTLP, so a harness transcript is never the agent's trace source — and Inspect emits no `ToolEvent` at all for a bridged agent, which is what a user-owned agent is. [Report](docs/spikes/execution-backend.md). | Compiling cards to Inspect `Task`s: it buys sandboxing for code specdeck never executes, provider portability needed at two call sites, and an audit log of a run whose trace already arrives by another route, while coupling the card format to Inspect's `Task` surface. |
| 2026-08-16 | **Domain events in the event-selector vocabulary** — a reserved `specdeck.*` attribute namespace, stamped on the span it describes, with the legal marker names declared alongside the tool vocabulary so lint rejects an unknown one. In an eval the simulator stamps them; in production the agent's own instrumentation does, which is what lets the same property serve the runtime monitor. | Domain events as first-class spans, which would put non-semconv spans in a log whose value is that it *is* the semconv; and dropping the concept, which would cost the format its escalation wire and rewrite its own example card. |
| 2026-08-16 | **Wire palette, superseding the 2026-08-15 entry** — the Dwyer patterns **plus bounds** over a fixed, introspectable measure vocabulary. `latency: under 120s` and `response_tokens under 400` are bounds, and no Dwyer pattern expresses them: `response_tokens` is a sum across `chat` spans, so no event selector reaches it. Lint rejects an unknown measure the way it rejects an unknown tool. | Dropping bounds from the card format, which would make a latency budget report-only and remove two wires from the format's own example card. |
| 2026-08-24 | **The simulator reports its own marker** — each simulated turn returns `{reply, marker, done}`, and an undeclared marker is refused rather than stamped. It is the party that knows whether it accepted the answer. | A second classifier call per turn to infer the marker: it doubles simulator calls and adds a second pinned prompt to grade a reaction it did not have. The cost accepted is that the simulator scores its own state, which is why the marker vocabulary is declared and enforced. |
| 2026-08-24 | **The provider seam is one function, `complete()`, and a bare model string means Anthropic** — a prefix (`openai/gpt-5`) names a departure from the default. | Requiring a prefix everywhere: `spec.lock.toml` pins `claude-sonnet-5` and every cassette keys on the model string, so it would re-key every recording on disk and cost a live call each to record what is already there. A plugin registry was also rejected — two call sites do not need one. |
| 2026-08-24 | **A conversation ends when the simulator says `done`**, with `--max-turns` as a backstop. | Ending only on a turn cap: every run would then finish mid-argument, and the cap would silently become the scenario's length rather than its limit. |
| 2026-08-24 | **Card-mechanics language in prose is a lint warning**, carved out of "never style-police the SME zone". Prose describing the card's own pass/fail machinery — "do not fail this card", "fails only if", ALL-CAPS emphasis — reproducibly makes the judge return commentary instead of verdicts, and an ungraded criterion fails closed. Warning, never error: the SME's words stay theirs. | A suggestion, which the severity rule as written implies and which never blocks — it would have hinted at two wasted live judge calls rather than prevented them. And an error, which would put lint in a position to reject the SME's own prose. |
| 2026-08-24 | **The lockfile pins the wire block too**, in its own `wires_hash` per card, computed from the compiled property IR rather than the wire text. | Folding wires into `rubric_hash`: a stale-lock error could then no longer say whether the prose or the wires moved, and those are owned by different people. And leaving wires unpinned, which let `modify_reservation: never` be deleted while the lock verified clean and the cell ran green. |
| 2026-08-24 | **The cost rate table is a data file, not a lock pin** — a built-in `src/specdeck/rates.toml` of per-provider, per-model USD-per-million-token input and output rates, optionally merged under a `rates.toml` beside the card, carrying a `verified` date that every rendered figure prints. A model with no entry yields no number at all — `n/a` naming the model, never a substituted rate and never $0.00. | A `[rates]` section of `spec.lock.toml`: `--relock` rewrites that file from a fixed template and would drop it, and an ordinary vendor price refresh would then read as card drift on every card. And cctx's mid-range default for an unrecognised model — it prices sessions that already happened, where a plausible figure beats nothing; specdeck reports a live run, where a fabricated rate would put an invented number in front of a user as if it had been measured. |
| 2026-08-24 | **A rate key prices its own family and that family's dated ids, nothing else** — a match is accepted only where the rest of the model id is empty or a `-YYYYMMDD` release date. | Bare longest-prefix matching: `claude-opus-4-9` would inherit the retired `claude-opus-4` price at three times the Opus tier, which is the substituted rate #16(b) exists to forbid, printed as a confident estimate. |
| 2026-08-24 | **A merged rate table carries the older of the two `verified` dates.** | Taking the override's date wholesale: an override that only adds a model restates nothing about the built-in rows, so its date would stamp figures nobody rechecked with a freshness claim nobody made. |
| 2026-08-24 | **Variance is the spread of per-run credit over the passing runs** — the min-max range and the population standard deviation, taken over exactly the set `credit_mean` is taken over, plus a "gate mixed, 4 pass / 1 fail" clause only when the gate itself went both ways. The 2026-08-15 entry said the cell reports "variance" and left the term undefined; this defines it. No UNSTABLE verdict and no quarantine lane — those stay with variance attribution, a later phase, because they would change the exit-code contract. | The binomial standard deviation of the gate pass rate: it mostly restates the "4/5 runs" the headline already prints, while the credit headline is the number that actually hides something — "credit 3/3 over 4 passing runs" reads identically whether the runs scored 3, 3, 3, 3 or 1, 3, 3, 5. |
| 2026-08-24 | **The dollar estimate prices the agent's traced tokens only**, and the report line says "agent tokens only" rather than leaving the scope to be assumed. specdeck's own judge and simulator spend is not in the figure ([#80](https://github.com/jacquardlabs/specdeck/issues/80)). | Pricing specdeck's own spend now: `provider.complete` returns a bare string and a cassette stores only the reply text, so it would mean widening the provider seam and re-recording every cassette — and cassettes are Phase 3 mutation-runner fixtures, not throwaway recordings. Inventing the counts instead was never on the table. |
| 2026-08-24 | **Per-model usage read off a trace carries the provider in the model id** — `Trace.usage_by_model` keys on `gen_ai.response.model` prefixed with `gen_ai.provider.name` when it names a real one, so `openai/gpt-4o` prices against a `[rates.openai]` section the user added. A bare id stays bare, the way `provider.split_model` already reads one. | Keying on the bare id and passing a `provider=` override at each pricing call site: nothing did, so a model the default provider never serves read as unpriced even when the resolved table priced it — and #17's baseline and #15's cap would have inherited the same blindness from the same shared surface. A `(provider, model)` tuple key was also rejected: it widens the surface two later waves read, for information the id already carries. |
| 2026-08-24 | **A `rates.toml` merely found beside the card cannot abort a run** — a broken one prints a note naming the file and the run continues on the built-in table; a table named on `--rates` still exits 2, because the user asked for that table. | Exit 2 on both paths: an unrequested optional file pricing a dim secondary figure would stop a card that had nothing wrong with it, and README documents exit 2 as "the run could not start". Reporting `n/a` instead of the built-in figure was also rejected — the cost line would then read "no rate table" when there is one, and threading the reason into the report is scope this wave does not have. |
| 2026-08-24 | **Every card gets three wires it did not author** — `stop_reason: not truncated`, a latency budget, and a token regression against a committed baseline — compiled to the same property IR an authored wire produces and merged only in `cell.run_cell_async`, never in `compile_wires`. Built-ins are therefore **evaluated but not pinned**: `wires_hash` keeps hashing what a human wrote. | Folding them into `wires_hash`, which would make a specdeck release that moves a default read as card drift in every user repo, with a `--relock` hint for a card nobody edited. And a parallel mechanism outside the IR, which would give the report, the evaluator and lint a second kind of check to know about. |
| 2026-08-24 | **The default latency budget is a `--latency-budget` flag with a constant default of 120.0 seconds**, and a bad value routes as a user error (exit 2) rather than a pydantic `ValidationError` (exit 3). | A `[budgets]` section in `spec.lock.toml`: it would couple a per-project performance number to a drift-detection file whose contract is refuse-and-exit-2, so a budget change would read as card drift. And no free latency wire at all, which reduces the issue to two built-ins for no gain — all five committed cards already author a latency wire, so the merged behaviour is byte-identical to today either way. |
| 2026-08-24 | **A card opts out of a built-in by authoring the same subject** — no new card syntax, no `latency: off`, no `context:` key. Dedup is on the compiled `Property.id` alone, so tier is no part of the match and a card writing the wire under `credit` moves the check off the gate. **A known gap, accepted rather than solved:** `stop_reason: not truncated` is the only rule that subject takes ([wires.py](src/specdeck/wires.py) rejects every other), so a card that genuinely cannot avoid truncation can demote the wire but not relax it. An override, unlike a built-in, *is* authored and so *is* hashed into `wires_hash`. | A `- latency: off` form in the `wire` block: it widens the card format for a case the dedup rule already covers, and an opt-out that is not a wire would need its own hashing rule to keep a lock honest. And a `builtins: none` context key, which would widen the closed `CONTEXT_KEYS` tuple. |
| 2026-08-24 | **The token baseline is its own file, `spec.baseline.toml`**, beside `spec.lock.toml` and keyed card x cell through the same `lock_key`, holding the **median** (lower half on an even count) of the runs' `total_output_tokens`, recorded by `--update-baseline`. The tolerance is **0.10 — a chosen number, not a derived one**. The wire is **gate tier**, so a regression exits 1 through the existing path. **A card with no baseline recorded gets no wire at all**, and `--update-baseline` refuses rather than recording a 0 from a trace that reported no usage. | A `baseline_tokens` key inside `spec.lock.toml`: the lockfile refuses and exits 2 on any drift, and a measured token count moves on every real run, so ordinary variance would become a hard wall. A mean, which one spike moves; a max, which ratchets upward forever. The plain interpolating median, which over an even count averages two runs into a token count no run produced. And keying by card alone, which #15's matrix makes wrong the day it lands — the cell key is held at `"default"` so that fills a slot rather than migrating a file users have committed. |
| 2026-08-24 | **JUnit XML maps a run onto `<testcase>`, not a cell** — `<testsuites>` per invocation, `<testsuite>` per cell, `<testcase>` per run, `<failure>` naming the gate wires and criteria that failed. Hand-rolled with stdlib `xml.etree`. The cost is stated on every failing row: because a cell passes at k of N, a tolerated failure is a red row beside exit 0, so each `<failure>` message carries "the cell needs 4 of 5 and got 4" and the suite's `system-out` repeats the cell's own verdict. | One `<testcase>` per cell, which can never contradict the exit code but shows CI a single opaque row for a five-run cell — a report a human cannot act on, which is the thing #18 asked for. Reporting a tolerated failure as `<skipped>` was also rejected: it hides a run that really did fail. And the `junit-xml` package, which is not on the four-package allowlist. |
| 2026-08-24 | **The exit-code registry is written down in one place** (`cli.EXIT_CODES`): 0 the cell passed, 1 it failed its gate, 2 the run could not start, 3 specdeck itself broke. **4 is reserved and unissued** for "the matrix did not complete: budget" (#15). #18's regression exit is not a new code — the token baseline is a gate wire, so a regression is exit 1. | A distinct exit code for a regression: it would split "this card broke" from "this card got more expensive" at the cost of a fifth state, when the baseline is already expressed as a gate and a gate already exits 1. Reusing 4 for anything else was rejected so wave 4 extends the registry rather than colliding with it. |
| 2026-08-24 | **The baseline file is written only after the cell has run**, though the figure it holds is folded into that same run's bound beforehand — so a run refused in `run_cell` (a trace count that disagrees with `--runs`, a missing cassette) leaves a committed baseline untouched, and a path that cannot be written exits 2 like `--junit-xml`. | Writing it in `_builtin` before the cell was validated: a refused run silently overwrote a committed baseline with a number from a cell that never ran, and exited before the report, so not even the "recorded from a failing run" note fired. Refusing to record from a failing run was rejected again — that is still an open product question, and refusing would answer it. |
| 2026-08-24 | **A recorded token baseline is positive at both ends** — `--update-baseline` refuses a run whose `gen_ai.usage.output_tokens` total to 0 as well as one that reports none, with separate messages, and `CellBaseline` rejects a non-positive figure on read. | Guarding only the writer: a hand-edited `output_tokens = 0` then exited 3 ("specdeck itself broke") on every later run of that card until a human deleted the file, for a file the user owns. And guarding only the recorded median, which would have taken 100 from the runs [0, 100, 100] — a cost measured off a set containing a run the instrumentation got wrong. |
| 2026-08-24 | **The budget cap counts every token the matrix causes to be spent — specdeck's own judge and simulator calls and the agent's own model calls — and is honest that it can only *prevent* the first.** specdeck's calls are checked before each one and cost nothing in replay; the agent's happen inside `adapter.run`, which spends the money and reports it afterwards, so a single agent run can exceed the whole remaining budget before specdeck sees a token count. Pre-flight refuses a matrix it cannot price and `check()` refuses a column the cap can no longer afford; an overshoot aborts the columns that are left. The overshoot is bounded by matrix concurrency x cell concurrency and is **printed in the report, the README and the PR**, never described as prevention. Three fail-closed rules, because charging zero for a run nobody can price is the failure the cap exists to prevent: under a cap, an unpriced column model refuses the whole matrix by name; a trace carrying `loop`'s `"unknown"` model aborts; a trace where `reports_output_tokens` is False aborts. | Counting specdeck's own spend only, which is fully preventable but ignores the money a provider matrix exists to spend. A declared per-run token ceiling per column, which would put a number in the matrix file nobody can know before the first run. And a pre-flight dollar forecast from recorded cassettes: the judge cassette is keyed on a trace that does not exist yet, so a first run has no basis and the figure would be invented — which the 2026-08-24 rate-table row already refuses of every cost figure. |
| 2026-08-24 | **A budget stop is exit 4, the code reserved for it, and `stopped_early` is a property of the column statuses rather than of the cap.** A cap reached on the very last charge stopped nothing, so that matrix completed and exits 0 or 1 with the overshoot stated; only a column actually skipped or cut short makes the answer unknown. A matrix's code is the worst of its columns: 4, then 2 or 3 for a column that raised (a user error against anything else, so the 2-vs-3 split survives), then 1, then 0. | Exit 1 for a stopped matrix, which tells a CI parser the card regressed when in fact nothing ran. Exit 2, which claims the run could not start after three columns already had. And ranking a known gate failure above an incomplete grid: a matrix missing a column has not answered the question that was asked, so its headline verdict is not the one to route on. |
| 2026-08-24 | **The matrix is declared in its own TOML file passed as `--matrix`, never in the card**, as two axes of named entries whose product is the columns; each entry's `config` table is opaque and handed verbatim to `AgentAdapter.run`, and the only key specdeck reads is `model`, to price the column. Columns run under **asyncio**, `--matrix-concurrency` at a time, forced to 1 under `--live`. The baseline's cell slot is the column's own name, through one `matrix.cell_key`, with the single-cell path keeping `"default"`. | Putting a `variants:` or provider roster in the card: `CONTEXT_KEYS` is closed, `variants:` is reserved for Phase 4, and a card naming a developer's model roster breaks the two-owned-zones rule. Threads: the whole path below the CLI is already coroutines and the provider is an `httpx.AsyncClient`, so a pool would need a second client, a second copy of the cell's semaphore, and a lock the budget does not otherwise need. Running live columns in parallel: turn 1 of every column builds the identical simulator prompt, so two would race one cassette — and folding the column name into the cassette key would re-key recordings CLAUDE.md designates Phase-3 mutation fixtures. |
| 2026-08-25 | **The cap is checked between the runs of a column, not only between the columns, and the pre-flight prices specdeck's own pinned judge and simulator beside the columns' models.** The stated overshoot is therefore what is already in flight — matrix concurrency x cell concurrency of specdeck's own calls plus the one agent conversation each running column is inside — never `--runs` conversations begun after the cap is known blown. A trace that reports usage on some chat spans and not others is **charged for what it reported and the silent spans are counted as unmetered**, so the figure reads as the floor it is. | Leaving the check between columns alone: at `--runs 5` a single column could spend 5000x a hard cap and still exit 0, because nothing was skipped. Pricing the judge and simulator only when the report renders: an unpriced model is charged $0.00 through `rates.estimate`, so under `--live` the cap could never trip on the one axis specdeck can genuinely prevent. And aborting a partly-metered trace under the cap, which would refuse the shape a real adapter has — usage attached to the last message of a turn, as `tests/fake_agent.refuses` already produces — so it is counted and named instead, with the question of whether it should refuse left to #86. |
| 2026-08-25 | **A cycle counts as bounded only by a wire naming a node *in* it** — `never` or `at_most` on that tool, or an `after k <marker>` escalation whose follow-up tool is in the cycle (exactly `wires.named_tools`) — and the definition-fed obligations are checked over the whole deck, from an `--agent-def <module:attribute>` introspection whose **depth is printed in every report**, at every depth including `not introspected`. Depth is computed from what came back, never from what was asked, and each obligation reports itself SKIPPED below the depth it needs. LangGraph is read by duck typing through a `PROBES` seam, so langgraph stays off the dependency allowlist and the fake in `tests/fake_graph.py` is written to the documented accessor chain rather than verified against a real install. | Counting a trace-level `bound` — `latency: under 120s`, `response_tokens under 400` — as bounding a loop: it bounds a run, not a loop, and the format's own example card carries one, so the ERROR would ship unreachable on any deck that bounds latency. Per-card obligations, which would red a deck for a cycle the card beside it bounds when there is one agent behind both. And scanning `card.prose` for tool names, which would be a second rule inside the SME's block for near-zero recall — a card reads "the agent refuses the change", never `cancel_reservation`. |
| 2026-08-25 | **The policy denominator ships as a clause *inventory*, not the clauses x cards matrix docs/measurement.md describes**, and `specdeck coverage` is its home: clause count per document, count per section, and the one deterministic uncovered signal — a policy document named by zero cards. Extraction is a structural rule over the markdown (a column-zero list marker starts a clause, indented lines continue it), never a model call, so the denominator is reproducible. `specdeck coverage` exits 0 on any computed result and `coverage.py` binds neither `Severity` nor `Finding`, both held by tests. | Rendering the matrix on the only attribution available today, which is document-level: it would put an identical mark in every cell of a document's rows and be read as per-clause attribution — the silent degradation the blindness rule exists to prevent. An explicit `clauses:` context key, deterministic but a card-format change that no committed card carries and CLAUDE.md forbids auto-editing into one. And judge-assessed attribution, which is nondeterministic, needs a second pinned prompt in the lockfile, and moves the denominator whenever the judge model moves. The matrix is deferred, not cancelled; the blocker is the missing clause-to-card predicate. |
| 2026-08-25 | **Path coverage takes its denominator from introspection and never from the trace, and its evidence is a recorded interim: node name == tool name, an edge hit when two `execute_tool` spans with those names are consecutive in `trace.ordered`.** A trace records what happened, so edges derived from it would make denominator equal numerator and read 100% forever. The interim is in `ir.bound`'s spirit — named, not merged silently: a LangGraph graph from #21 declares edges through router, chat and hand-off nodes that no trace can ever mark hit, so **the figure understates what ran**, and that sentence is printed on every line carrying a figure, in docs/measurement.md and here. It is one function, `coverage._hit_edges`, so replacing it is a one-function change. Report-only: `PathCoverage` has no `passed` or `ok`, and `specdeck run`'s exit stays `0 if cell.passed else 1`. | A reserved `specdeck.node` trace attribute the agent's own instrumentation stamps, as `specdeck.marker` already is — the eventual fix and the right one, deferred because every existing trace lacks it, so shipping it today would give a denominator of edges against a numerator of zero (https://github.com/jacquardlabs/specdeck/issues/89). Deriving edges from the trace, which is not a denominator. And narrowing the denominator to the edges the mapping can see, which would hide the understatement instead of printing it. |
| 2026-08-25 | **Supersedes the cycle row above: a cycle is bounded by a wire naming a tool the cycle can *call*** — the tools its own nodes bind (`AgentDescription.node_tools`, filled by the probe and read through `introspect.bounding_tools`), plus a node that is itself a declared tool, which is the raw-SDK shape. | 2026-08-25 | **A card is excluded from unnamed-policy candidacy only in a directory that also holds a card naming a policy**, and a file under the deck that does not parse as a card is carried on `Coverage.unreadable` and printed above the tables rather than aborting `specdeck coverage` with exit 2. | Excluding every card the caller passed: `cli.coverage` parses each walked `.md` as a card, so an orphan under `cards/policy/` arrived as a card and filtered itself out — #19(a)'s one deterministic signal had no input that could produce a row. | 2026-08-25 | **Requested and executed are separate wires** — `<tool>: never_executed` (the existing `never`, kept as its short spelling and compiling to an identical property, so no committed lock moves) and `<tool>: never_requested`, which also matches a tool call in a `chat` span's output messages and a denial span. | 2026-08-25 | **A card declares its own traces** — `context: traces:` takes one glob, resolved against the card's directory and containment-checked per match, and `specdeck run <directory>` runs every card it finds, aggregating to 2 on any user error, 1 on any failed gate, else 0. `--trace` becomes an override rather than the only binding, and a card that does not parse is one `SuiteError` among the results rather than the end of the run.
